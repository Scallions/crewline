# Crewline · 前端 MVP

依据 `Crewline_MVP_PRD.docx` 和「设计UI UX」对话中最新的 **Crewline 智能 Agent 协作工作台**设计实现。中英文界面，React + Vite，适配桌面与手机。

## 本地运行

```sh
npm install
npm run dev -- --host 127.0.0.1 --port 4173 --strictPort
```

预览：<http://127.0.0.1:4173/>。构建：`npm run build`。业务测试：`npm test`。打包兼容检查：`npm run test:sites`。

## 已实现的交互

- 默认示例工作台；新建需求、模板快捷输入、参考附件信息、聊天补充。
- 对话支持预算、页数、期限、移除/恢复对比工位，以及更经济的团队组合。例如「预算改为 450 USDC」「改成 10 页」「去掉对比矩阵」「换便宜一点的组合」。其他补充会记录到需求说明，不声称经过实际模型理解。
- 每个第三方工位的三名候选，可按价格、一次通过率、交付速度排序；选择后实时重算报价。
- 可编辑交付目标、预算、页数、期限、工位；显示工位输入、输出及验收规则。
- 确认团队 → 模拟托管 → 依赖执行 → 交付预览 → 验收结算；支持暂停、恢复和演示推进按钮。
- 预算或余额不足时阻止启动；启动与验收防重复扣款；未验收不结算。
- 一轮返工，仅重跑撰写及质检；再次拒收可创建争议，保留托管。
- 实际可下载的 Markdown **示例文件**、JSON **模拟收据**。
- 订单搜索与状态筛选、Agent 市场、消息、模拟钱包入金及账本。
- 右上角支持中英文切换，语言偏好保存到当前浏览器；用户输入和报告正文保留原始语言。
- 作者 Agent 配置、HTTPS 端点格式/报价等本地校验、演示上架、编辑、暂停接单。
- 浏览器本地保存订单、聊天、选择、余额与作者配置。帮助中心可「打开示例需求」，不清除现有订单。

## 演示边界

这是可交互的前端 MVP，使用规则与定时器模拟 Planner 和 Agent。没有实际 LLM、登录验证、Webhook 请求、文件内容解析、钱包连接、USDC 支付、链上身份、真实质量检查或后台仲裁。参考附件只保存名称、大小和类型，不上传文件正文。市场与作者履历是演示数据。示例报告明确标注不包含真实研究结论。

执行约每 6.5 秒推进一个工位；暂停和待验收状态保持不动。数据保存在当前浏览器的 `crewline.frontend.v1`，不同浏览器的数据互不共享。

## PRD 与图稿的取舍

- 沿用图稿的浅色/墨绿样式、导航、聊天消息、工位卡片、候选选择、确认、执行及交付流程。
- 图稿的质检单独报价与 520 USDC 总价不一致。遵循 PRD 的平台独立质检规则：采集 120 + 对比 140 + 撰写 180 = 440；Token 储备 60；含质检的平台费 20；合计 **520 USDC**。质检不可替换成第三方。
- 图稿底部是流程说明缩略图，本项目将其实现为可操作的弹窗和真实状态，不重复铺成静态画板。
- PRD 允许 Markdown 交付，因此下载真实 Markdown 文件，没有把示例内容伪装成 PDF。
- 手机端使用「需求对话 / 团队与报价」切换，保留完整流程。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/domain.mjs` | Agent 目录、报价、状态转换、模拟账本、需求规则、交付内容 |
| `src/App.jsx` | 应用壳、导航、持久化、模拟执行时钟 |
| `src/workspace.jsx` | 聊天、工位方案、推荐团队、报价 |
| `src/dialogs.jsx` | 候选对比、编辑、托管、预览、返工、验收 |
| `src/pages.jsx` | 订单、市场、作者、消息、钱包 |
| `src/components.jsx` | 通用控件、对话框、交付卡片与下载 |
| `src/styles.css` | 原图设计样式、响应式、交互状态 |
| `tests/domain.test.mjs` | 预算、账本、状态机及返工等业务不变量 |
| `docs/reference/` | 本地原始 PRD 与最新设计图（不上传公开仓库） |
| `design-qa.md` | 视觉与交互验证记录 |

品牌与演示头像使用内置 Imagegen 依据参考图生成；界面图标使用 Phosphor。所有图片均随项目保存，无外部图片依赖。

通过 GitHub Actions 发布到 [GitHub Pages](https://scallions.github.io/crewline/)。每次推送 `main` 或手动触发 `Deploy Crewline to GitHub Pages`，工作流都会安装依赖、执行测试、构建，并发布 `dist/client`。构建时根据 Pages 的实际路径设置资源前缀，兼容项目子路径。

原始 PRD、设计参考图和本地 QA 截图仅保存在本地，不包含在公开仓库或部署产物中。保留了模板的 Sites 打包适配：构建结果位于 `dist/client`，服务适配位于 `dist/server`。
